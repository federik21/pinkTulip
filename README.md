# B Battles — online prototype

Two-to-four-mage, unofficial TypeScript prototype with an authoritative WebSocket server, a shared rules engine, and a React client. Card names and effects are original placeholders, not a reproduction of the published card set.

## Start locally

Install dependencies once:

```bash
npm install
```

In **terminal 1**, leave the server running:

```bash
npm run dev -w @brw/server
```

In a **separate terminal 2**, leave the client running:

```bash
npm run dev -w @brw/client -- --host 0.0.0.0
```

Open **http://localhost:5173** in one tab to play against AI, or in separate tabs, browser windows, or devices for multiplayer. The WebSocket address `ws://localhost:8080` is not a website to open in a tab.

1. The first mage creates a room and invites up to three other mages to join it.
2. In the lobby, each human mage chooses a **starting magic school** from the available list. Multiple mages may choose the same school. For solo play, the creator clicks **Add AI opponent**.
3. The creator can choose **Rooms per color**: **Automatic**, **1**, **2**, or **3**. Automatic uses **1 for two mages, 2 for three, and 3 for four** when the battle starts. Changing this setting clears everyone's readiness; only the creator can change it. Wait for everyone to join and choose a school, then each mage clicks **Mark ready**. A valid school is required before marking ready; changing it cancels that mage's ready status.
4. The battle **starts automatically as soon as all joined mages are ready**, with a minimum of two. A lone ready creator waits for at least one other person. Unused seats do not block a two- or three-mage battle. Invite everyone before the final ready; new seats cannot join a running battle.

Each joined mage receives a separate starting room, grimoire, cube pool, color, and turn. A fifth participant is rejected. Leaving a lobby removes that participant and transfers creator duties if necessary; leaving a running battle preserves the seat and pauses the game until reconnection. Rejoining a disconnected running seat is supported, but is not authenticated.

### Playing against basic AI

- Create a room, click **Add AI opponent**, choose your school, then **Mark ready**. No second browser or external AI service is needed. The creator can remove AI seats before the battle starts; adding/removing AI resets readiness.
- AI seats choose their school, study and prepare automatically. During play they pursue exposed enemies, cast prepared spells, activate hidden spells, use free quest rewards, attack and control evocations, and answer their own reaction/Soul Tithe decisions. This is a simple deterministic heuristic, not a difficulty-tuned or learning opponent.
- AI commands use the same authoritative rules and costs as human commands, one command approximately every 450 ms. Decisions use the AI's own cards and public board facts, not opponents' hidden cards or future draw identities. The creator still continues **B** and **Cleanup** normally.
- Friends and AI may share a room. With the current single-school **Agony** library (36 shared cards), AI rooms are capped at **three total mages** so every mage can complete the first mandatory Study. No extra cards are created.
- AI waits whenever a human turn/decision is pending, a human is disconnected, or nobody is viewing the room. AI seats survive saved-session restores and cannot be claimed by a joining human. AI commitments clear the human Undo/Redo window.
- Focused checks: `npx vitest run apps/server/test/ai.test.ts apps/server/test/bot-room.test.ts apps/server/test/bot-network.test.ts`; browser flow: `npx playwright test e2e/ai-opponent.spec.ts`.

### Saving a session for later

The server scripts (`npm run dev -w @brw/server`, `npm run start -w @brw/server`) save running battles to `apps/server/saves/sessions.json`. Set `SAVE_FILE=<path>` to use another file; leaving it unset, empty or `off` (as the tests do) turns saving off, in which case an empty room is discarded as before.

- A battle is saved automatically after every change. The header **Save session** button (shown during a running battle when saving is on) writes the file immediately and confirms it. Lobbies and finished games are not saved.
- When every human mage leaves, the battle is kept instead of being deleted, and the room list shows it as **saved** with the mage names. A server restart (including the dev watcher) restores it with humans disconnected and AI seats still server-controlled.
- To resume, each mage joins the room (**Join room**, not **Create room**) using the same **mage name**; a matching name takes that mage's own seat, otherwise the first open seat. The game stays paused until all mages are back. Undo/Redo history is not saved. The file holds every hidden hand and deck, so treat it as private; there is no authentication.

### Starting-school setup

- While in `LOBBY`, submit `SELECT_STARTING_SCHOOL { playerId, schoolId }`; valid school IDs are `agony`, `technomancy`, and `alchemy`. The choice is stored in `Player.startingSchoolId` and is public. A new seat has no selected school, and missing or invalid choices cannot become ready through `SET_READY`.
- Selecting or changing a school **does not deal any cards**. A new mage's personal deck, hand, and personal discard are all empty in the lobby. Changing to a different valid school clears only that mage's readiness; selecting the same school again does not. When all joined mages meet the start requirements, the server automatically applies `START_GAME` for the creator.
- At `START_GAME`, the authoritative server validates the aggregate selected-school supply and **atomically removes 7 actual physical cards per mage from their selected shared school**, before the first event. These seven are the mage's **entire starting personal grimoire, not their hand**: the first **6 go into `personalDeck`**, the seventh goes into the **personal `discard`**, and **`hand` stays empty**. There are no extra 12 base personal cards. Each school has 36 physical cards. Four mages choosing the same school allocate 28 distinct cards and leave 8 in that school's supply. A failed start cannot partially allocate cards.

- **Choices and personal discards are public; hand identities are private to their owner. All future deck identities and draw order are masked even from the owner.** The first event has no starting-deck recap or initial spell cards; removing that presentation does not change the **6 personal-deck / 1 personal-discard / 0 hand** allocation. Reconnecting to a running seat preserves its choice and existing cards; it never repeats the starting allocation. Starting-school selection is unavailable after the lobby.
- Setup moves existing cards; it creates no copies. Total physical spell supply stays **120 = 108 school cards + 12 Forgotten spells**, independent of mage count. The seven starting cards per mage come out of those 108, not an additional supply. Their IDs and `schoolId` are preserved: the initial seventh-card personal discard is a setup exception, not a change to ordinary subsequent school-discard routing. Cards permanently removed after casting remain accounted for in the removed-card zone.

For a second device on the same Wi-Fi, open the Vite Network URL (for example `http://192.168.1.5:5173`). The client connects to port 8080 on that same host. Allow the ports through the firewall. `VITE_WS_URL` can override the WebSocket endpoint; the server port can be changed with `PORT`.

If startup reports `EADDRINUSE`, another server already owns port 8080. Stop the earlier server with Ctrl+C before restarting; do not run the client command inside the server's running watch process.

## Implemented glossary

- Unused spell cards do not display a **Ready** badge; used preparations still show **Spent**. **Active** means an activated, hidden **Trap** (`TRAP`) or **Protection** (`PROTECTION`); it has spent its activation action and awaits its condition. Activation is not a cast and chooses no room or target.
- The four spell types and icons are **Combat ⚡** (`COMBAT`), **Contingency 🔮** (`CONTINGENCY`), **Protection 🛡️** (`PROTECTION`), and **Trap** (`TRAP`) with the original **bear-trap SVG**, not a mouse emoji.
- On spell cards, the **type icon appears once beside the type label**. The **large central icon identifies the card's school**, matching Study choices: **Agony ☠**, **Technomancy ⚙**, **Alchemy ☿**. School identity comes from the card's `schoolId`, independently of its type. Forgotten spells use **✺** labeled **Forgotten spells**; unknown or absent school IDs use **✺** labeled **Unaligned spell**. These presentation changes do not alter card effects, setup, or other rules.
- The central chamber's special cards are **Forgotten spells**. Protected starting rooms are **Rose Mage cell**, **Blue Mage cell**, **Amber Mage cell**, and **Green Mage cell**, matching the current seat colors.
- The title is **B Battles**; the phase and neutral competitor are **B**, and the central chamber is **B Chamber**. Internal identifiers `BLACK_ROSE`, `blackRose`, the `@brw` package namespace, and room/seat IDs remain unchanged for save/protocol compatibility; the implemented wire type for Combat is `COMBAT`.

A **sticky banner** below the navbar shows the acting mage or your turn and carries **Undo / Redo** (only when available; absent offline) and, on your turn only, **End turn (n/2)**, disabled at 0/2 and enabled from 1/2. The dashboard has no tab bar: the dock buttons **Physical actions / Spells / Evocations / Quests** choose which labelled panel it shows, from anywhere on the page, with no duplicate command buttons. Its **✕ Close** button or **Escape** closes the dashboard and restores launcher focus without losing selections. Physical actions holds physical menus; Spells holds Action-phase prepared cards, Active/ongoing spells and held Forgotten spells; Evocations holds model controls and retinues; Quests holds personal quests. Study/Preparation selections stay **above the banner**. **Physical actions is selected on entering Action and after a paid evocation finishes**; Evocations is selected on entering `EVOCATION` or starting an owned model's activation. Ordinary state updates preserve the selected panel and spell target. After you choose Explore or Attack, the sticky banner also shows shortcuts to finish the action without opening the dashboard: **Move N** (or **Finish moving early**), **Attack <name>**, **Activate room** and **Finish action** (skips remaining effects). The map and targeting remain usable with every panel, and Undo/Redo and End turn live in the sticky banner outside the panels. The map has **− / 100% / +** zoom controls (50–300%; click the percentage to reset), plus keyboard **+ / − / 0** on the focused map, Ctrl/trackpad-pinch wheel zoom and two-finger touch pinch; one finger still scrolls the zoomed map. Prepared Trap, Protection and Ongoing cards print their effect inside the card.
- Mage rosters sit **in the main game column below the map**, with full native details **open by default**. Damage, hand count/card limit, tokens, VP and acting status remain visible when collapsed. Every mage publicly shows **Trap: N · Protection: N**, plus **Spells left: N** counting only unused prepared slots—not held cards or already Active magic. Foreign Active entries show **Hidden active spell** with their public **Trap / Protection type and icon**. Names, physical card IDs, rules, triggers and bindings of another owner's hidden spells remain private. Expanded details retain attributes, cube supply and **View evocations**. The map uses the full content width; the **Chronicle opens from the dock as a right-hand overlay drawer**, not a permanent side column. It starts closed, updates live, locks background scrolling and supports Close, Escape and backdrop dismissal with focus restoration.
- Quick-access controls respect mobile safe areas and provide touch targets at least 44 px high. Long controls scroll inside the bounded dashboard; compact spell cards scroll horizontally. Choosing a spell, beginning movement or activating an evocation closes the quick dashboard for board interaction. **Spell target selection and confirmation float just above the dock**, so casting does not require scrolling beneath the map. Normal action costs, pending acknowledgements, turn ownership and disconnect guards are unchanged.
- The header's **Quick reference** button opens the rules reference in a named dialog. The board's **Lodge information** button opens detailed map help, room descriptions and both room/mage color legends in another dialog; no legend strips remain above the map. Both support **Escape** and **Close**, contain keyboard focus while open, and return focus to their opening button. Quick reference is not a tab.

Only your own hidden Trap/Protection bindings get target markers; opponents' hidden targets remain private. Public ongoing effects are visible to everyone. Room-bound effects are not attached to their occupants. Markers follow models and disappear when the binding expires or resolves, including undo/redo and Cleanup.

They never reveal another owner's hidden spell or binding. Untriggered hidden spells return privately to their owner's hand at Cleanup; ongoing spells expire to their ordinary discard destination.

### Authoritative feedback events

- The optional public `GameState.feedbackEvents` feed contains at most **512** engine-authored resolution events, each with a **UUID** and round: `DAMAGE`, `CONVERT`, `MAGE_DEFEATED`, and `SPELL_TRIGGERED`. Damage pulses report actual inflicted damage; conversion pulses report ownership changes with the wound/instability total unchanged. Clients use these facts, not log parsing or hidden-card disappearance.
- Defeat recaps show the final hitter, contribution **ranks/ties and VP**, any **exclusive-color bonus**, **cubes returned to each owner**, cleared damage and the **named respawn room**.
- Actual one-shot **Trap / Protection triggers** and defeats enter an ordered, dismissible notification queue. Ongoing reactions produce **no trigger popup**; hidden arming and untriggered expiry produce **no popup or hidden-detail disclosure**.
- Initial join/reconnect state is a **baseline**, not a replay of old notifications. Event-ID deduplication prevents duplicate broadcasts or Undo/Redo from replaying already-seen feedback; rewinds remove withdrawn queued events. Feedback respects **reduced motion**, announces damage/conversion accessibly, and uses **nonmodal** notices and pointer-transparent board pulses so controls remain usable.

## Round flow

**B → Study → Preparation → Action → Evocation → Cleanup.** The engine, WebSocket API and React client support summoning, model targeting and evocation control.

Every phase has a brief, dismissible announcement. B and Cleanup remain visible until the creator continues, so players can read the event and scores. Study and Preparation finish automatically once all participating mages submit.

### BR Phase

- Each mage starts with **2 physical tokens**, refreshed to exactly **2** at the beginning of every round; unused tokens do not accumulate.
- Draw and resolve one of 12 event cards: neutral instability in random unfinished rooms, or 1–2 black damage to every mage.
- BR is a neutral **scoring competitor**, with publicly tracked VP and kills. Its black damage competes with player-owned cubes for mage-defeat majorities; its room cubes compete for room rewards. A B finishing blow credits its kill count, never a player's kill quest. Player-owned damage cubes return on defeat, and the mage respawns in their own starting room.
- At the end of B, when the creator continues, each mage **without an unsolved quest** receives exactly one. Solved/claimed quests do not count and return to the quest discard. Incomplete quests and completed-but-unclaimed rewards remain unsolved and are retained without drawing a replacement. This resolution happens once, tracked by `blackRoseResolved`.
- Each mage has **quest limit 2**. If anyone holds more, B stays visible until each affected owner selects **exactly their overflow** and submits `DISCARD_QUESTS { questIds }`. Selected quests go to the shared quest discard without completion rewards; retained quests stay private.
- While quest selections are pending, the creator cannot continue again and **nobody can begin Study or draw their 2 grimoire cards**. Once all quests fit, Study starts automatically and each mage draws up to 2 personal grimoire cards. With no overflow, the creator's continue proceeds directly to Study; no empty selection is needed.

### Study

- The shared library contains **Agony**, **Technomancy**, and **Alchemy**. Each has **12 distinct printed spells with 3 physical copies each**, for 36 cards per school; every physical card has a unique ID. Agony is still one school, not six identical copies.
- Select **four blind library draws in any school combination**, including four from one school. Clicking a school adds **one** entry, not an immediate draw. Use **Remove 1 &lt;school&gt; card** or **Reset selection** to revise the combination, then explicitly choose **Draw selected cards**. No card identities are previewed. A school is selectable while its available supply exceeds the entries already selected from it; it does not need four copies to contribute one draw.
- The client sends `DRAW_STUDY { playerId, deckIds: [four school IDs] }`. The server still accepts legacy `deckId` for four draws from one school, but records all four actual physical IDs in the owner's private `studyCardIds`. The full hand is shown after drawing, but **only these four newly drawn library cards are enabled** for the mandatory **exactly two-card discard**. Older held cards and the two personal-grimoire draws remain disabled, even when they share a school with the new cards. Eligibility IDs are never sent to other mages or spectators.
- **Normal round-one Study starts from an empty hand:** entering Study draws 2 of the 6 personal-deck cards, then the mage draws 4 school cards and discards 2: **0 + 2 + 4 − 2 = 4 cards in hand**, with **4 cards still in the personal deck and the initial 1 card in personal discard**. Those ordinary Study discards return to their origin school's discard. There is **no automatic first-round hand overflow or mandatory hand-limit discard** from this setup. The Study school need not match the starting-school choice. Additional draws can still cause overflow; the **7-card limit before preparing slots**, later-round draws, discards, and phase flow are unchanged.
- **Shared spells normally return to their own school’s discard pile**, whether discarded during Study, resolved, left uncast in prepared slots when the next round begins, or spent to exit a starting room. Unselected Preparation cards stay in hand. Active hidden spells remain until revealed or Cleanup; public ongoing spells persist through defeat until Cleanup, following bound mages after respawn. At Cleanup, **untriggered hidden spells return to hand**; ongoing spells are discarded. Personal spells normally return to the mage's grimoire discard. The mandatory Preparation hand-limit discard below is an explicit exception.
- Forgotten spells cannot be discarded during Study or spent on a discard-to-move. Only the mandatory hand-limit selection can put one into personal discard; otherwise keep it until cast.
- **General draw rule:** whenever a draw pile runs out, shuffle its own discard into a new draw pile and continue taking the remaining cards, including partway through a multi-card draw. This applies to personal grimoires, schools, quests and events. Each school needs enough cards across its draw and discard piles **for the number selected from that school**; held, prepared, Active hidden, and ongoing cards are never recycled. Study draws up to 2 personal cards if the remaining grimoire cards are already held. Permanently removed Forgotten spells never recycle; their separate supply has no discard pile.

### Spell effects and target categories

- **Self** targets only the caster’s mage. **Mage** targets another mage, **Evocation** one evocation, **Model** another mage or an evocation, and **Room** a room and its models. Only a printed **Self** target can select the caster's mage, including support, Protection and ongoing spells; friendly evocations remain eligible for support. Room effects can still affect the caster as an occupant. Finite ranges require a straight hex line; infinite range ignores line of sight. Protected-starting-room rules apply to both.
- **Heal N** removes up to N wounds from each selected model and returns actual colored cubes to their owners. A room heal affects **every mage and evocation** there, including the caster and friendly models. It never grants kill or victory rewards.
- **Convert N** replaces up to N other-colored cubes with available caster cubes. On an enemy model it changes damage-cube ownership without changing wounds. **Damage conversion on the caster's own mage or owned evocations is ignored**, including triggered instructions: no cube, supply, wound or conversion-feedback changes. The cast still consumes its normal action/card, and all other effects resolve normally. Room conversion still changes live instability ownership, not damage on its occupants, even when friendly models occupy that room. Removed colored cubes return to their owners. B cubes can be converted, but unattributed wounds cannot. Scored/rebuilt room history cannot be converted.
- Healing and conversion process colored contributors in player seating order, then B; healing then removes unattributed wounds. Conversion skips the caster’s existing color and stops when their supply runs out. Ordinary combined spells resolve instability, conversion, healing, then damage. Conversion is not new instability/damage and awards no immediate completion/kill quests or exclusive-color bonus.
- **Friendly damage immunity:** never inflict player-sourced damage or ordinary damage conversion on that player's mage or evocations, including triggered instructions and target-defeated area damage. Support may still heal friendly evocations; room instability conversion is unchanged. **Peak of Agony** is a **Room spell at range 2**, with three ordered moments: **2 damage** to every enemy model in the selected room (skip your mage and friendly evocations); convert your mage's **last 2 damage cubes received from other mages** into B black, returning the colored cubes without changing wounds; then **Pain 2**. The second moment explicitly scopes neutral conversion to the caster independently of the chosen room; it does not enable ordinary friendly damage/conversion. Neutral Pain and B events remain neutral. Old saved friendly-fire flags are ignored, and previous canonical Peak cards upgrade to the corrected target, range and three moments.
- **Pain Mark** triggers only when the bound mage deals damage with their own physical attack or spell. A controlled evocation's activation/attack never counts, nor does damage from a room effect or quest reward—even when that effect occurs inside a physical action. Damage origin is recorded per effect, so a nested spell retains its own spell origin rather than inheriting a surrounding room/quest action. Generic traps such as Torment still react to their printed damage conditions.
- **Liquefy the Pain** summons a Succubus in your mage's fixed defeat room before scoring/respawn, then grants its owner a **free interactive activation**, even during another mage's turn or evocation activation. Move and attack in either order using the top banner, or finish early; no extra action or token is charged. Finishing restores the interrupted turn, pending physical effects, or evocation's remaining movement/used attack. A failed summon never activates an older servant. Saved canonical summon-only copies upgrade automatically.

### Card moments

- Trap and Protection constructors accept an optional **`triggerText`** description, such as `triggerText: 'When you are defeated'`, alongside the authoritative `trigger` and `triggerEffects`. Define it in the card patterns in `packages/game-engine/src/cards.ts`. Cards show this condition first, with triggered effects and explanatory rules below; activation/reveal dialogs and private Active reminders use the same ordering. Keep `rulesText` as the full explanation for compatibility: `getSpellDescription(card)` separates its leading condition without repeating it. Older saved cards without `triggerText` use their existing condition text or trigger metadata. Display text never changes trigger matching or reveals an opponent's hidden details.
- A card's printed effects are an ordered `moments` array in `packages/game-engine/src/cards.ts`. Each moment is a tagged union value, the TypeScript equivalent of a Swift enum with associated values: `{ effect:'DAMAGE'|'HEAL'|'CONVERT'|'INSTABILITY', amount }`. Build them with `moment.damage(1)`, `moment.convert(2)`, `moment.heal(1)`, `moment.instability(1)`.
- Moments resolve strictly in array order, so convert can come before or after damage, and a card can repeat an effect with different amounts, e.g. `moments:[moment.damage(1), moment.damage(2), moment.instability(1)]`. Each moment is a separate resolution step that can trigger its own feedback and interrupts.
- The Chronicle records public card plays and numbered moments in their actual resolution order, including revealed traps, ongoing reactions and free quest rewards. Face-down activations remain anonymous until revealed. A moment may explicitly select the caster or all models in the caster's room independently of the card's primary selection.
- If a mage is defeated during a moment, resolution pauses for the defeat effects and then resumes with the remaining moments.
- Existing cards keep their previous order (instability, convert, heal, damage); reorder them in `cards.ts` to change it. Saved sessions that still contain the old flat `damage`/`heal`/`convert`/`instability` fields are upgraded automatically on load.

### Four spell types and Alchemy

**Combat** (`COMBAT`) and **Contingency** are thematic labels: hurtful effects such as damage, instability, or conversion are Combat; otherwise they are Contingency. They keep the normal preparation, sequencing and one-action casting rules.

**Trap** and **Protection** spells are **activated, not cast**. Select the prepared card and confirm activation in its dialog: **no room, model, or dummy is selected**. `ACTIVATE_SPELL` spends one turn action and the prepared slot, leaves the card face down, and marks it Active; it does not emit a spell-cast event. Its type is public, but its identity and trigger remain private.

**Revealing is optional.** At a matching condition, the owner may choose a spell, then **Reveal and resolve**, or **Keep all hidden** for a later occurrence. Some spells **force their target from the triggering event**; the dialog displays that fixed target without a target selector, and the server rejects any attempt to redirect it. Otherwise choose a legal target. If several of that owner's cards match, the owner chooses the next one to resolve. Different owners act in play order starting at the first-player token. Opponents receive only a generic waiting status, never the private choices or replay payload. Revealing removes the card from Active before resolving it, so it cannot trigger itself twice; the revealed card goes to the owner's personal discard (**Memories**).

Agony's forced-target traps are:
- **Torment:** when an enemy model deals damage, target that exact mage or evocation, not its controller or damage recipient. Inflict 2 damage, then summon a Succubus in the dealer's original room, even if the retaliation defeats or destroys it. Damage to either mages or evocations can trigger it; room activation alone cannot.
- **Master of Pleasure:** when another mage solves a quest, target that exact quest-solving mage. Inflict 2 damage, then summon a Succubus in their original room. No bystander may be selected.
- **Liquefy the Pain:** when **your own mage** is defeated, summon a Succubus in the room where that mage was defeated. Resolve within the defeat reaction window, **before points, cube return, or respawn to their cell**. Neither an enemy's defeat nor the attacker's ownership triggers it, and the room cannot be changed.

The declarative `Card.triggerTarget` selects `EVENT_MODEL`, `EVENT_ACTOR`, or `EVENT_ROOM`. `TriggerCondition.relationTo` can compare ownership with the event model instead of the default actor, so own-defeat conditions also work against neutral damage. Existing printed target categories, protected-room rules, and snapshot-generation safety remain in force.

**An effect is the whole card/action text; a moment is one instruction (one period).** Finish the complete moment, including all affected models and defeat processing, suspend the remaining effect, resolve matching reactions, then resume. Nested reactions resolve depth-first. Room activation completes its current reward moment before interrupting. A defeated mage loses remaining physical-action effects. A pathological chain exceeding 128 reactions rejects the root action atomically.

Combat/Contingency **ongoing** effects bind to their selected model and **persist through mage defeat**, whether the owner or bound mage is defeated. After respawn the same ongoing card follows the bound mage; stale pre-defeat events cannot affect the new life. A destroyed evocation's ongoing card remains but is inactive, never transferred to a replacement summon. Ongoing cards are still discarded once at **Cleanup**. Hidden Trap/Protection cards have **no board binding or board token**. Legacy room/model scope fields on their conditions are checked against the event at trigger time, not a room chosen during activation. At Cleanup, an owner's unrevealed Active cards return to Hand by default; the private **At Cleanup** setting can send them to Memories instead. Revealed cards remain in Memories. Active cards are actual physical cards, not extra copies. Pending decisions and reveals are history barriers; activation itself supports exact undo/redo.

### Preparation

- Each mage has **card limit 7**, checked against their **entire hand before removing prepared spells**. If over, select **exactly the excess number of different held cards** and submit `DISCARD_HAND_LIMIT { cardIds }`, then prepare. Preparation is blocked until the limit is met.
- This mandatory selection sends **every selected card to the owner's PERSONAL discard**, even a school spell or Forgotten spell. Its ID, `schoolId` and Forgotten-spell flag are preserved; it is not removed from the game. Later retrieval/draw and casting use its normal rules. This exception does not change Study/cast/discard-exit routing.
- Hand-limit selection is available only in Preparation, before that mage has prepared. No overflow means no selection: an empty limit-discard command is rejected, not required to proceed.
- **Prepare 2–4 spells** by tapping **one hand card, then its destination slot**: **1, 2, 3, or ✧ Quick**. Selecting a card alone does not place it. **Done** enables after at least **2 spells are placed**, including a numbered spell plus Quick; preparing all four is optional. The slot toolbar and Done stay visible while scrolling through your cards.
- Choose destinations in any order. A card can occupy only one slot: assigning it elsewhere moves it, replacing an occupied slot returns the displaced card to your unplaced hand, and **✕** empties a slot. **Reset selection** clears all placements and the pending card. The chosen numbered positions stay exact, even with empty earlier slots; the wire retains `preparedCardIds` with explicit `null` placeholders and optional `rapidCardId` for Quick. Legacy contiguous ID arrays remain valid.
- Numbered spells cannot skip an **occupied, unused** earlier slot, and **only one numbered spell may be cast per turn**. The **Quick slot** (formerly Flexible) is independent of that ordering, but every cast still uses one of the shared two turn actions.
- Unselected cards remain in hand. Uncast ordinary prepared cards go to their origin's discard when the next round starts. **Unused Forgotten preparations return to hand**, never a discard pile.

### Action

- Each mage's authoritative wizard stats are **maximum HP 10** (`wizard.health`), **attack 2** (`wizard.attack`), and **movement 2** (`wizard.movement`). Wounds are tracked separately in `damageCubes`; health is not remaining HP.
- Each mage has **2 physical action tokens for the entire round**. Beginning **Explore** or **Attack**, and an additional evocation activation, each consume **1 physical token and 1 turn action**. Spells and discard-to-move use a turn action but **no physical token**. Summoning is a **free Grey room effect**, never a separate paid action.
- Alternate turns with **up to 2 actions total**, tracked by `activation.actionsUsed`: Explore, Attack, every spell cast (numbered, Quick, and Forgotten), discard-to-move, and paid evocation activation all count. **Two Explores leave no spell cast available on that turn.** Numbered plus Quick, spell plus Explore, and discard-to-move plus Explore each use both actions. Discard-to-move works from any room (once per turn, adjacent space, never into a starting room); leaving a starting room is one use of it. Choose **End turn** in the top banner after one action to keep remaining resources, except when the last action must leave your cell. After the second action fully resolves, the turn hands off unless a usable free quest reward is ready; solve it or choose End turn to defer it. Unused cards and physical tokens remain for later turns. The turn also ends early if no legal options remain. With no other eligible mage, the same mage can begin a new turn with a refreshed two-action budget.
- The **Chronicle** records each mage's **turn start and turn end**, including early End turn, automatic handoffs and a fresh turn for the same remaining mage. Pending physical effects, reactions and free quest reward windows finish before the end entry. Undo/Redo restores these entries with the rest of the turn; temporary evocation control does not create a new mage Action turn.
- **Discard-to-move can use any unused prepared spell:** any numbered or Quick slot, including later numbered spells and spells that cannot currently be cast because the numbered-cast quota is spent. The card must not already have been cast or activated. Held/unprepared cards, used/Active spells and Forgotten spells remain ineligible. Discarding consumes that preparation and one turn action, but no physical token or numbered-cast quota. Discarding a later numbered spell does not skip an earlier unused spell for casting. A prepared spell may be discarded to leave a protected cell without casting its effects.
- Top-level **Explore** and **Attack** open their respective physical-action menus using `BEGIN_PHYSICAL_ACTION { kind }`. The token/action is consumed **only at begin**, not for subsequent primary or room effects.
- Explore's **Perform 2 movements** (`PERFORM_MOVEMENT`; the displayed count follows `wizard.movement`) enables adjacent steps using `EXPLORE_STEP`. **Finish movement early** (`END_EXPLORE`) stops movement early. Completing movement leaves the room effect available if unused; it does not silently close the whole menu.
- Attack's **Inflict attack** (`INFLICT_ATTACK { targetId }`) deals `wizard.attack` damage, normally **2**, to a real enemy mage or evocation **in exactly the same hex (distance 0)**. Adjacent targets are not legal mage attacks. Evocation attacks separately require both models to occupy the **same room**. **Dummy targets are exclusive to spell cards**: neither mage physical attacks nor evocation attacks can use them, including forged commands carrying a dummy flag. With no legal enemy, skip the remaining physical effects or finish the evocation instead.
- Both menus offer **Activate the room** (`ACTIVATE_ROOM`, optionally `roomTargetId` for Emerald) and **Skip remaining effects** (`SKIP_PHYSICAL_EFFECTS`). Resolve primary then room, or room then primary, each at most once. Using both automatically closes the menu. Skip is legal at any point, including during movement, preserves effects already resolved, and never refunds the token.
- While a physical menu is pending, other mage commands—including spells, paid model activation, another physical action, discard exit, End turn and Pass—are locked. A zero-token mage still finishes the pending effects or skips. Room activation waits until movement has ended.
- **Activate a Grey room** through `ACTIVATE_ROOM` to summon **1 Cadaver (Undead) at the mage's position when the effect resolves**. Merely entering or occupying Grey does not summon. A reconstructed Grey room offers **2 Cadavers**, capped by the mage's **3 living owned evocations**: with two already owned, summon only one; at three, summon none. Destroyed models free their owned slots. There is **no extra token or physical-action cost** beyond beginning Explore/Attack.
- Grey replaces the former Ivory color. Its room effect is `SUMMON_CADAVER`, replacing `DRAW_LIBRARY`; it never draws from or recycles a shared school deck. **Direct paid summoning has been removed**: `SUMMON_EVOCATION` is not a valid game action, and even a malicious legacy WebSocket payload is rejected with **Unknown game action**, without changing state.
- All mages share a finite miniature supply: **3 Succubi and 6 Cadavers** total, in addition to the **maximum 3 living owned evocations per mage**. Summoning from an empty supply does nothing; destroyed models return to supply. The Evocations panel shows live remaining/total counters, derived from models in play so undo and decision replay cannot desynchronize them.
- Every Cadaver has **movement 2, base attack 2, health 2**. Its special effect is **blank for now**: no Wounded Fury or other ability; wounds do not increase its attack. Evocations persist across rounds until destroyed.
- **Succubus (Demon)** has **movement 2, base attack 1, health 3** and Wounded Fury (**1 + its damageCubes**). Agony spell moments summon it; Cross and Delight resolves Summon → Pain 1 → free activation of that exact summoned model. Templates live in `EVOCATION_TYPES`.
- **Soul Tithe** (Succubus ability): whenever its owner's mage is about to take damage, one of those damage cubes may go on the Succubus instead, **wherever it stands** (no same-room requirement). The attacker's cube is placed on the Succubus (or it takes black damage if the source is the B); the mage takes one less. Several Succubi are asked in model-number order and never take more cubes than were inflicted; a Succubus may be destroyed this way.
  - **Prompt:** unless the Succubus has its **Auto** switch on (default off, owner-only, `SET_EVOCATION_AUTO`), the engine pauses the action in `pendingDecision` and the owner answers with `RESPOND_SOUL_TITHE { accept }` from a modal popup; everyone else sees a waiting notice and every other action is rejected until the answer arrives.
  - **Replay:** engine resolution is synchronous, so the pending state is the untouched pre-action state plus a server-private `resume` (original action and answers so far). Answering replays the whole action with those answers; `publicState` strips `resume`.
  - **History:** a paused action and its resolution are undo/redo barriers (history is cleared), as are switch changes.
- **Activate evocation** (`ACTIVATE_EVOCATION`) during Action is an additional paid activation of one owned model: 1 token and 1 turn action. Its movement, attack and finish buttons appear in the **top acting-player banner**, without reopening the dashboard. It locks mage commands until the evocation finishes both effects or the player chooses to finish. A model may receive further paid activations if resources allow; these do **not** spend its later free Evocation-phase activation.
- **Cast spell** costs **1 turn action and no physical token**, including Quick, dummy, and Forgotten casts. Cast at most one numbered spell per turn; the Quick spell can be the other action if unused. Select a prepared spell, a highlighted target room, then confirm. Ordinary spells deal up to **4 damage** and/or **2 instability**, with ranges 0–4 and model or room targets. **Forgotten spells cannot be cast from hand**: save them for a later Preparation and assign a numbered or Quick slot. They obey that slot's ordering and quota. Legacy `CAST_POWERFUL_SPELL` commands are rejected.
- **Finite spell range follows a straight, contiguous hex line without turning**, not a hex radius. The target must share the caster's `q`, `r`, or `q + r` coordinate, at most the printed number of hex steps away; range 0 permits the caster's hex. This applies to room, mage, evocation, dummy, and Forgotten-spell targets. From `(0,0)`, range 2 reaches the center and the first two hexes along each of the six directions, but never `(1,-2)`, `(-1,-1)`, `(2,-1)`, `(-2,1)`, `(1,1)`, or `(-1,2)`, even at a higher finite range. **Infinite range (∞) ignores both distance and line of sight:** any non-starting room is in range, including off-axis rooms. Printed target categories and ownership restrictions still apply, including when revealing traps or resolving quest rewards. Infinite ranges survive WebSocket updates and saved-game reloads. Movement may still turn between adjacent steps; mage and evocation physical attack ranges are unchanged.
- **Mage, Evocation and Model** spells all offer an explicit **dummy target**, including healing, conversion, Trap/Protection and ongoing cards. Choose any **non-starting room within straight-line range**, occupied or empty; no real mage or evocation is required. A dummy cast resolves only the spell's **printed room instability**, never damage, healing, conversion or model-bound effects. It creates no hidden or ongoing binding: the spell is spent and discarded normally (Forgotten spells are permanently removed), costs **1 turn action and no physical token**, and still obeys numbered order, quota and the shared two-action limit. **Self and Room** spells retain their normal targeting and cannot use dummy mode. Existing reactions to the caster's **SPELL_CAST** still occur normally.
- **No friendly fire:** attacks and damage-only individual spells cannot target the controlling mage or friendly evocations. Support may select friendly evocations; only Self spells can directly select the caster's mage. Room/individual damage and ordinary damage conversion always skip friendly models, including Peak of Agony's room-damage moment and triggered instructions. Peak's separate caster-scoped neutral conversion still resolves before its Pain 2. Instability applies to the target's original room even if damage defeats and respawns them.
- In a **starting room**, a mage cannot cast, begin Attack, activate a room effect, or buy an evocation activation: **Explore** out, or **discard any unused prepared spell** to move exactly one adjacent space for **1 turn action and no physical token**. The discard exit can be used once per turn. Mages cannot voluntarily enter or reenter any starting room; defeat still respawns them there. Evocations can never enter any starting room. Regular rooms remain revisitable. Starting rooms and models inside them cannot be targeted by spells or physical attacks. A mage inside a starting room also ignores damage from other players' ongoing, reactive, room and splash effects; only B (Black) damage ignores that protection. A mage in a starting room may still control their models during the free Evocation phase.
- Player damage places **1 attacker-owned cube per damage actually inflicted**, limited by the attacker's available supply. Damage still applies if fewer cubes are available; overkill cannot add cubes beyond the victim's remaining health. The supply is shared with room instability.
- **Defeat timing:** finish the current damage moment, then resolve damage/defeat reactions while the lethally wounded mage is still in place with its damage ledger intact. A heal may prevent defeat; in that case award no defeat points, trophy, kill credit or neutral defeat reward, do not respawn, and do not run "if the target is defeated" moments (e.g. Visceral Fire's follow-up). Only a mage still at lethal damage after reactions is finalized. Scoring uses the post-reaction ledger, including any conversions, and later spell moments continue against a rescued mage normally.
- All evocation damage is sourced to its **controlling mage**. That owner's `cubes.onWizard` tracks cubes on enemy mages, `cubes.onEvocations` separately tracks cubes on enemy summons, and `cubes.onBoard` tracks committed room instability. These and `cubes.available` share the same 25-cube supply. Victims record ownership in `damageByPlayer`.
- Destroying an evocation returns **all cubes on it to their owners** and removes the model, with **no VP, mage-kill, or kill-quest reward**. An evocation defeating a mage still credits its controller normally, including contribution scoring and final-hitter kill/quest credit below.
- When a mage is defeated, rank positive damage contributions, **including B's black damage**: base rewards are **4 / 2 / 1 VP** for the first three distinct contribution ranks; later ranks receive zero. Use **dense ranks**: equal counts share a rank, and the next distinct count receives the next rank (1, 1, 2 rather than 1, 1, 3). Each tied positive award is reduced by **exactly 1 VP**, with a minimum of **1 VP**, regardless of tie size. Explicit zero prizes stay zero. For example, contributions of 4 / 4 / 1 yield **3 / 3 / 2 VP**. Zero contributions do not compete.
- Award **+1 VP** to the sole contributor if **all damage on the defeated mage is accounted for by that mage's colored cubes**, with no neutral black damage. Damage inflicted after running out of physical cubes does not qualify as colored cubes. This bonus is separate from rank rewards and kill quests.
- Return all damage cubes on the defeated mage to their respective owners, clear that mage's damage, and respawn them in their starting room. Cubes those owners placed on other mages or in rooms stay committed.
- The final hitter still receives kill and kill-quest credit, but there is **no additional flat kill VP bonus**. Contribution scoring also applies when a neutral event delivers the finishing damage.
- **End turn** keeps unused resources and is available after a completed/skipped physical action, a spell, or a discard exit, but never during a pending physical menu or active evocation. Spending both turn actions hands off automatically. The redundant **Pass for this round button has been removed**. The legacy `PASS_ROUND` API is legal only with **0 physical tokens and no unused prepared spells**; held, unprepared Forgotten spells do not block passing or automatic exhaustion.
- Exhausted mages with no legal spells, physical actions, or discard exit are automatically skipped; a permanent pass is not needed to drain the round. When everyone has passed or cannot act, enter **Evocation**; if no models exist, it immediately proceeds to Cleanup.

#### Physical-menu examples

1. **Explore → Perform 2 movements → adjacent steps → Finish movement early if needed → Activate the room.** This uses the destination's room effect. Finishing the final movement step does not automatically activate it.
2. **Explore → Activate the room → Perform 2 movements → steps or Finish movement early.** This uses the origin's room effect; a Grey Cadaver stays at the spawn hex instead of following the mage.
3. **Attack → Inflict 2 damage to a model at distance 0 → choose an enemy → Activate the room**, or activate the room before inflicting damage. The attack still needs a legal same-hex enemy when it resolves. If a Crimson effect defeats that target first, skip the remaining attack rather than hitting its respawn.
4. **Skip remaining effects** closes either menu whenever desired, even before using its primary effect. Paid **Activate evocation** is separate: it controls an existing model and never summons or triggers a room effect.

Room activation is unavailable in starting rooms and for a reconstructed special already spent this Action phase. Emerald needs a valid target within distance 1 of the activated room. Legacy engine `EXPLORE`/`PUNCH` commands remain for compatibility, but the client/network smoke use the explicit menus above, not bundled start/end timing flags. Browser verification of the rewritten client is separate from the network smoke.

### Undo and redo

- **Undo action** and **Redo action** restore recent non-drawing commands, including movement, action/token costs, spell use, contributions, damage, scores, completed quests and summoned model identities. Redo restores the exact result, rather than rerunning randomness.
- History is authoritative and private to the server, bounded to 32 command snapshots. Clients receive only their own availability flags and labels, never snapshots or hidden cards.
- Draws, quest draws, random discard retrievals, phase changes and connection/roster changes clear history. Even activating an empty draw source is a barrier. A later movement can be undone without exposing or replaying an earlier draw.
- A same-phase turn handoff can be undone by the previous actor until another player successfully acts. Failed or unauthorized commands do not alter history. New actions discard the redo branch.

### Evocation

- At phase entry, reset **every surviving model's `activated` flag**, independently of any paid Action activations. Each model then receives **one free activation**, costing no mage action or token.
- Alternate **owners**, starting with the first player who owns an unused model. The active owner chooses which unused owned model to activate. Skip owners without unused models; an owner may therefore activate consecutive models after everyone else is exhausted.
- Only **one model may be active at a time**. `EVOCATION_STEP` moves it one adjacent space at a time, up to its movement allowance (Cadaver: 2); no starting-room entry is allowed. Movement is optional.
- Movement and the single attack may be resolved **in either order**, or either may be skipped. `EVOCATION_ATTACK` targets an enemy mage ID (player ID or wizard ID) or evocation ID in the **same room it occupies**. Both positions must belong to one common room's `tiles`: distinct hexes within a multi-hex room are legal, but a different room is illegal even when adjacent. A successful attack sets `attackUsed` but leaves unused movement available. Friendly models and models in starting rooms are protected.
- **Finish evocation movement early** (`END_EVOCATION_MOVEMENT`) sets the remaining movement to zero without consuming an unused attack. If the attack has already been used, this finishes the activation; otherwise the player can still attack. After both movement and attack are resolved, the activation finishes automatically.
- `END_EVOCATION` skips all remaining effects, whether or not an attack has already occurred. In Action it resumes the mage's turn (or automatically advances if exhausted); in Evocation it selects the next eligible owner. These rules also apply to free activations granted by a spell's final moment.
- Used models cannot activate again in this phase. When no unused surviving models remain, resolve **Cleanup**. With no evocations, this phase immediately proceeds to Cleanup.
- Each living model has a stable owner-local number **1–3**. Destroying one frees its number without renumbering survivors. Its board circle and detail card share its mage's tint. Use **View evocations** in a mage's details to open that owner's retinue in the **Evocations** tab; opponents' details are read-only and can also be shown/hidden there. Own-model controls do not depend on opening a mage card.

### Technomancy school

- A second library school (12 spells x 3 copies). Its spells assign **upgrades** (six cards x 3 copies: Cerebral implant, Corrosive plasma, Muscular implant, Regenerating ichor, Reinforced dermis, Tendon implant) to evocations, at most one per model. A Cadaver gains +1 health while upgraded; Reinforced dermis adds +2 health. If a model already has one, its owner keeps one and the other returns to the deck; nothing is assigned when no copy is left.
- Spells can activate another mage's evocation under the caster's control: the controller's colour applies, it may attack the owner, and the controller and its evocations are immune to that damage.
- The **Colossus** (undead, move 2, attack 3, health 4, three models, larger icon) joins the shared supply. Entry shock: it inflicts 3 damage on each other mage that enters its room (not its owner, not other summons, and not when the Colossus itself moves).
- Tendon implant models may move their speed at the end of the Black Rose phase (optional, before Study; bots skip it).
- Pick-one decisions (upgrade replacement, removed evocation, library look) use the `CHOICE` pending decision and `RESPOND_CHOICE`.

### Rooms and Cleanup

Regular rooms have **6 colors**, with the creator's selected **1, 2 or 3 rooms of every color**. Automatic sizing is resolved at `START_GAME`: **two mages → 1/color → 11 total rooms; three → 2/color → 17; four → 3/color → 23**. Each total includes the **central chamber and all four protected starting cells**, including unused seats. The smallest board relocates cells to its smaller perimeter; each mage is placed in their actual cell on the generated board. Explicit host overrides use the chosen size regardless of roster. **Only the regular rooms receive unique randomly assigned names.** The center is always **B Chamber**; starting rooms have the fixed color-based names **Rose Mage cell** (p1), **Blue Mage cell** (p2), **Amber Mage cell** (p3), and **Green Mage cell** (p4). Names are shared with all players and stay fixed for that battle. The board, target choices, logs, and evocation locations use room names rather than coordinates; internal room IDs and axial coordinates remain targeting details.

Room interiors show **compact, centered instability/capacity badges** with progress segments tinted by contributor, including light-gray B cubes. Rebuilt rooms show only **READY / USED** for their upgraded action, not completion progress or returned cube counts. Mage and evocation meters show **damage received**, segmented by contributor, rather than remaining health. Wounds inflicted without available physical cubes are separately labeled as unattributed. The physical-action menu appears in **Physical actions** above the map during the owner's Action turn. The board scrolls on small screens rather than shrinking its contents; detailed descriptions and the legend are under **Lodge information**.

Choose **at most one free room effect within each Explore or Attack menu**, before or after its primary effect; it never costs another action/token. `ACTIVATE_ROOM` uses the mage's position when it resolves. Starting rooms have no effect, and discard exits/spells do not trigger room effects.

If it is your turn and you have **one turn action left while still in your cell**, use it to leave via Explore or discard-to-move. **End turn**, permanent pass, and skipping/finishing that last Explore without moving out are blocked when a legal exit is available. Moving out satisfies the requirement even if an entry reaction then defeats you; an impossible exit does not deadlock the game.

## Architecture and scope

- `packages/game-engine`: deck definitions, immutable actions, events, quests, phases, combat and scoring.
- `apps/server`: in-memory room authority, readiness, action validation, hidden spells and draw piles, private bounded undo/redo history, state broadcasts.
- `apps/client`: phase-aware lobby and gameplay, spell selection/targeting, hex board, quest tracking, log, animations.

This implementation supports **two to four mages with Cadaver evocations, starting-school selection, Trap/Protection activation, and ongoing spells end-to-end**. It does not claim full official rulebook fidelity, other summon archetypes, official card/room text, authentication, or durable persistence. Reloading can reclaim a disconnected running seat by joining the same room; that seat is not authenticated. A battle disconnect pauses actions until the vacant seat is filled. Lobby departures instead free a seat and transfer creator duties if necessary. Rooms are deleted when all participants disconnect or the server restarts.
